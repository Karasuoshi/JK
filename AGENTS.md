# Julia's Kitchen — инструкция для агентов

Сайт с рецептами Юли: **https://karasuoshi.github.io/JK/**
Репозиторий: **github.com/Karasuoshi/JK** (ветка `main`).

Эта инструкция для любого агента: Claude, ChatGPT, Codex и других. Прочитай её целиком, прежде чем что-то менять.

## Как устроено

- База рецептов — это файлы в репозитории. **Один рецепт = один файл** `recipes/<id>.json`. Базы данных и сервера нет.
- После каждого коммита в `main` GitHub Actions сам проверяет рецепты, собирает сайт и публикует его (около 2 минут).
- Если в рецепте ошибка, сборка останавливается, и на сайте остаётся прежняя версия. Ошибку видно во вкладке Actions репозитория.
- Папку `_site/` и всё, что генерируется, руками не трогать и не коммитить.

| Что | Где |
|---|---|
| Рецепты | `recipes/<id>.json` |
| Фото блюда | `photos/<id>.jpg` |
| Оригинальная карточка Юли | `cards/<id>.jpg` |
| Категории | `data/categories.json` |
| Справочник продуктов | `data/products.json` |
| Схема рецепта | `schema/recipe.schema.json` |
| Промпт для карточки в GPT | `docs/CARD_PROMPT.md` |
| Пример рецепта | `recipes/pampushki-k-borschu.json` |

## Главные правила

1. **Ничего не придумывать.** Названия, количества, шаги и советы переносятся как у Юли. Если в карточке не хватает данных (нет времени, порций), поле не заполняется.
2. **Ошибки не исправлять молча.** Опечатки исправить можно. Если не сходятся цифры, нет ингредиента и т. п., рецепт переносится как есть, а пользователю коротко пишется, что именно не так.
3. **`id` = имя файла**: латиница, цифры, дефисы. Транслит названия: «Черничный пирог» → `chernichnyy-pirog`. Если такой `id` уже есть, это тот же рецепт: его надо обновить, а не создавать дубль.
4. **Сначала проверить, нет ли рецепта.** Смотри `recipes/` или https://karasuoshi.github.io/JK/data/index.json.
5. **Описание коммита:** `Рецепт: <название> — добавлен` / `— исправлен` / `— новая карточка`.
6. **После публикации** открой страницу рецепта `https://karasuoshi.github.io/JK/r/<id>.html` и проверь, что он появился. Писать «опубликовано» можно только после этой проверки.
7. Ключи, пароли и личные данные в репозиторий не класть: он публичный.

## Сценарий А. Юля прислала карточку (картинку)

1. Сохрани картинку как `cards/<id>.jpg` (JPG, до 1,5 МБ).
2. Фото блюда:
   - если умеешь кадрировать, вырежи фото из карточки без рамки, скотча и стикеров и сохрани как `photos/<id>.jpg`;
   - если нет, не указывай `photo`. Сайт сам вырежет правую верхнюю часть карточки. Если вырезалось криво, задай `card.photo_crop` в долях картинки: `{"x":0.49,"y":0.05,"w":0.47,"h":0.25}` (это значения по умолчанию).
3. Перенеси текст карточки в `recipes/<id>.json` по формату ниже. Укажи `"card": {"image": "cards/<id>.jpg", ...}`.
4. Пройдись по карточке и сверь ингредиенты и шаги. Например, ингредиент используется в шагах, но его нет в списке, или веса не сходятся. Найденное напиши пользователю.
5. Закоммить все файлы одним коммитом.

## Сценарий Б. Рецепт пришёл текстом (от Юли или от другого агента)

1. Создай `recipes/<id>.json`. Блок `card.image` не указывай.
2. Фото: если пользователь прислал фото блюда, положи его в `photos/<id>.jpg`. Без фото рецепт тоже нормально покажется.
3. Карточку в стиле Юли сайт нарисует сам при сборке: `https://karasuoshi.github.io/JK/cards-auto/<id>.jpg`.
4. Если нужна «настоящая» карточка, как Юля делает в GPT, см. сценарий В, пункт 3.

## Сценарий В. Вернуть рецепт карточкой или текстом

1. Найди рецепт в https://karasuoshi.github.io/JK/data/index.json по полям `title` и `keys` (продукты). Там же готовые ссылки:
   - `url` — страница рецепта;
   - `card` — картинка карточки (оригинал Юли или автоматическая);
   - `json` — полный рецепт.
2. Текст рецепта бери из `json`. Ссылку на карточку можно отдавать как есть.
3. Новую красивую карточку через генератор картинок (GPT) делай по `docs/CARD_PROMPT.md`:
   - сохрани результат как `cards/<id>.jpg`;
   - пропиши `card.image`;
   - сверь цифры на картинке с JSON: генераторы иногда искажают текст.

## Сценарий Г. Исправить рецепт

1. Поправь `recipes/<id>.json`.
2. Если у рецепта есть оригинальная карточка (`card.image`), а изменились количества или шаги, картинка устарела. Скажи об этом пользователю и предложи один из вариантов:
   - сделать новую карточку (сценарий В, пункт 3);
   - убрать `card.image`, чтобы сайт рисовал карточку сам.

## Формат рецепта

```json
{
  "id": "pampushki-k-borschu",
  "title": "Пампушки к борщу",
  "description": "Мягкие, воздушные, ароматные булочки…",
  "category": "vypechka",
  "tags": ["дрожжевое тесто", "к супу"],
  "servings": { "qty": [7, 8], "unit": "пампушек", "note": "по 60 г готовая" },
  "time": { "text": "2,5–3 часа", "note": "с учётом расстойки", "minutes": [150, 180] },
  "difficulty": "средняя",
  "equipment": "Форма Ø 20 см",
  "ingredients": [
    { "group": "Тесто", "items": [
      { "name": "Мука пшеничная", "key": "мука", "qty": 300, "unit": "г" },
      { "name": "Вода", "note": "тёплая, 35–38 °C", "key": "вода", "qty": 180, "unit": "мл" },
      { "name": "Соль", "key": "соль", "qty": 6, "unit": "г", "alt": "1 ч. л." },
      { "name": "Чеснок", "key": "чеснок", "qty": [1, 2], "unit": "зубчик", "optional": true },
      { "name": "Перец", "key": "чёрный перец", "amount": "по вкусу" }
    ]}
  ],
  "steps": [ { "title": "Опара", "text": "Смешать тёплую воду, сахар и дрожжи…" } ],
  "tips": ["Чеснок можно пропустить или уменьшить по вкусу."],
  "notes": [ { "title": "Важно", "items": ["…"] } ],
  "card": { "image": "cards/pampushki-k-borschu.jpg", "theme": "green",
            "sticker": "Ароматные, мягкие и очень вкусные!", "aside": "Ароматная заливка — секрет вкуса!", "footer": "…" },
  "photo": "photos/pampushki-k-borschu.jpg",
  "author": "Юля",
  "added": "2026-10-15"
}
```

**Обязательные поля:** `id`, `title`, `description`, `category`, `ingredients`, `steps`.

**Ингредиент:**
- `name` — как написано у Юли.
- Количество одно из двух:
  - `qty` (число или `[от, до]`) + `unit`;
  - `amount` текстом: «по вкусу», «щепотка», «для посыпки».
- `unit` — `г`, `кг`, `мл`, `л`, `шт.`, `ч. л.`, `ст. л.`, `зубчик`, `пучок`. Числа пишутся с точкой: `1.5`. Сайт сам покажет «1½» или «1,5» и пересчитает порции.
- `alt` — второе количество в скобках, как на карточке («1 ч. л.», «250 г»).
- `note` — пояснение («тёплая», «или 15 г свежих»).
- `optional: true` — «по желанию».
- `approx: true` — «около».
- `key` — продукт из `data/products.json` (раздел «По продуктам»). Правила:
  - именительный падеж, единственное число: `яйцо`, `курица`, `лук`, `сыр`;
  - для «Соль, перец» пишется список: `["соль", "чёрный перец"]`;
  - `null`, если продукта нет (например, «Танчжон — весь»).
  - Если продукта нет в справочнике, добавь его в `data/products.json` в нужную группу. Иначе он попадёт в «Другое».

**Остальные поля:**
- `time.minutes` — общее время в минутах (число или `[от, до]`). Нужно для бейджа «35 мин».
- `steps[].title` — короткий заголовок шага, если он есть на карточке.
- `tips` — «Советы». `notes` — другие блоки: «Важно», «Можно попробовать».
- `card.theme`: `green` (обычные), `plum` (бордовые), `terracotta` (коричневые).
- `card.sticker` — надпись на стикере у фото.
- `card.aside` — рукописная приписка у ингредиентов.
- `card.footer` — подпись внизу.
- `source` — откуда рецепт, если не Юлин («Рецепт из The New York Times…»).
- `tagline` — короткая рукописная строка под названием.

**Категории** (`category`): `zavtraki` Завтраки, `supy` Супы, `goryachee` Горячее, `salaty` Салаты, `zakuski` Закуски, `pirogi` Пироги, `vypechka` Выпечка, `deserty` Десерты, `sousy` Соусы и заготовки, `napitki` Напитки. Новую категорию можно добавить в `data/categories.json`, но только если пользователь попросил.

## Проверка

Если можешь запускать код:

```bash
node tools/validate.mjs      # проверка рецептов
node tools/build.mjs         # сборка в _site/
```

Если не можешь, проверка пройдёт на GitHub после коммита. Сайт обновится только при успешной сборке.
