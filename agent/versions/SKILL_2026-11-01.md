# Julia's Kitchen — добавление и правка рецептов

Работает по ядру Архитектора: LAWS, USER, STANDARD, STYLE, TOKENS (D:\Hive\Архитектор, репозиторий Karasuoshi/architect).
Блоки профиля: не нужны. Здесь — только особенности этого агента.

## Замысел
- Зачем: у Юли одна удобная книжка рецептов на телефоне — карточки превращаются в рецепты на сайте без её участия.
- Успех: каждая карточка из входящих — на сайте с первого разбора; ни одной ошибки, перенесённой молча; у важных ошибок есть ПРАВКИ.txt.
- Важнее всего: дословно как у Юли → ни одной потерянной карточки → сайт собирается без ошибок → скорость.
- Нельзя: придумывать данные; молча править что-то кроме опечаток; удалять файлы на D; формы редактирования на сайте; ключи и личные данные в репозиторий (он публичный).

## Где что лежит
- Сайт: https://karasuoshi.github.io/JK/ · Репозиторий: Karasuoshi/JK (ветка `main`, **публичный**).
- Главный источник правил — `AGENTS.md` в репозитории: формат рецепта, сценарии А–Г, категории, ключи продуктов. Этот навык связывает его с папкой `D:\Hive\JK` и доводит дело до публикации.
- Хозяйство агента — `agent/` в репозитории (на сайт не попадает): этот навык (`SKILL.md`, прежние — `versions/`), `STATE.md` (дела), `tests.md`, `LESSONS.md`. Журнал публикаций — в `README.md`.
- Папка с карточками: `D:\Hive\JK` (рабочая папка карточек, не копия репозитория). Доступ к компьютеру: только D:\Hive\JK. Другие папки, весь диск, управление компьютером — не просить.

## Команды пользователя

| Фраза | Что делать |
|---|---|
| «разбери входящие» | Разбор папки `1 — Входящие` (ниже) |
| «добавь рецепт» + текст/фото | Сценарий Б из AGENTS.md |

## 0. Подготовка (каждый раз)

1. Подключить репозиторий на запись: `add_repo` (owner `Karasuoshi`, repo `JK`, access `push`), затем клон, прочитать `AGENTS.md` и `agent/STATE.md`. Если `add_repo` отвечает «link your GitHub account» — GitHub не подключён к этому аккаунту Claude: работу сделать до коммита, а пользователю одной строкой сказать подключить GitHub в настройках claude.ai → Connectors, после этого «публикуй».
2. Папка `D:\Hive\JK` — через инструменты связанного компьютера: `device_list_dir`, `device_stage_files` (прочитать), `device_commit_files` (записать). Удалять и переносить файлы там нельзя — только записывать новые; что нужно удалить, перечислить пользователю.
3. Компьютер не связан с чатом — можно: рецепт по карточке или тексту, присланным в чат (сценарии А, Б), правка (Г), публикация. Нельзя: разбор входящих, папки 2–4 и список `00 — …txt` — сказать об этом одной строкой; что положить в папки, перечислить в ответе.
4. Контейнер одноразовый: незапушенные коммиты пропадут вместе с сессией. Разбор и публикацию делать в одном разговоре; если пользователь ещё не сказал «публикуй», в конце разбора спросить.

## Структура папки D:\Hive\JK

- `00 — КАК УСТРОЕНА ПАПКА.txt` — описание и **список всех рецептов** со статусами («на сайте», «есть правки (папка 3)», «ВАЖНАЯ ОШИБКА»). Обновлять после каждого разбора и публикации, вместе со счётчиком.
- `1 — Входящие` — сюда Юля/Артём кладут новые и исправленные карточки, имена файлов любые. Файл `_сюда кладёшь новые карточки.txt` не трогать.
- `2 — Карточки` — актуальная карточка каждого рецепта, `<Название>.jpg`. Совпадает с `cards/<id>.jpg` в репозитории.
- `3 — Поправить в GPT` — копия карточки с ошибками + `<Название> — ПРАВКИ.txt`.
- `4 — Архив/Старые версии` — прежние версии: `<Название> — версия N.jpg`, `<Название> — другое фото.jpg`. Ничего не удаляется.

## Разбор входящих

Для каждой картинки в `1 — Входящие`:

1. Застейджить и посмотреть (Read). Определить название рецепта.
2. Найти, есть ли рецепт: `grep -l '"title"' recipes/*.json` по названию, или по `id` (транслит).
3. **Новый рецепт** → сценарий А из AGENTS.md:
   - `cards/<id>.jpg` — JPG до 1,5 МБ (при необходимости пережать Pillow, quality 88);
   - фото блюда: вырезать из карточки Pillow'ом без рамки/скотча/стикеров → `photos/<id>.jpg`, посмотреть результат глазами; если не выходит — не указывать `photo`, сайт вырежет сам (`card.photo_crop`);
   - текст карточки дословно в `recipes/<id>.json`; новые продукты — в `data/products.json`;
   - сверить ингредиенты с шагами, цифры, время, порции.
4. **Исправленная карточка существующего рецепта**:
   - прочитать `3 — Поправить в GPT/<Название> — ПРАВКИ.txt`, проверить, что каждая правка сделана и ничего другого не испортилось (генератор мог исказить другие цифры);
   - старую карточку из `2 — Карточки` сохранить в `4 — Архив/Старые версии/<Название> — версия N.jpg`;
   - обновить `cards/<id>.jpg`, `photos/<id>.jpg` и JSON по новой карточке.
5. **Если нашлись ошибки** (новые или оставшиеся): записать копию карточки и `<Название> — ПРАВКИ.txt` в `3 — Поправить в GPT`. Формат ПРАВКИ.txt:
   ```
   Исправь, пожалуйста, на этой карточке только то, что ниже. Всё остальное (текст, цифры, фото, расположение) оставь точно как есть — ничего не перерисовывай заново.

   Рецепт: <Название>

   1. <что не так> → <как должно быть>
   ```
   Если у рецепта на сайте из-за ошибки неполные ингредиенты — пометить «ВАЖНАЯ ОШИБКА» в списке `00 — …txt`.
   Если всё исправлено — сказать пользователю, какие файлы в папке 3 теперь можно удалить.
6. Новую карточку записать в `2 — Карточки/<Название>.jpg`.
7. Обновить `00 — КАК УСТРОЕНА ПАПКА.txt` (список, статусы, число рецептов) и журнал в `README.md` репозитория.
8. `node tools/validate.mjs` и `node tools/build.mjs` — ошибок быть не должно. Посмотреть собранную страницу `_site/r/<id>.html` (Playwright, скриншот) — что фото и текст на месте.
9. Один коммит на разбор; сообщение по AGENTS.md: `Рецепт: <название> — добавлен` / `— новая карточка` (несколько — перечислить). В конце сказать пользователю: что добавлено, что ушло в папку 3 и почему, какие входящие можно удалить.

## Публикация («публикуй»)

1. `git push origin main`. Сборка на GitHub идёт около 2 минут; если в рецепте ошибка, сайт остаётся прежним.
2. Проверить, что сборка прошла (`gh run list -R Karasuoshi/JK -L 1`), и открыть `https://karasuoshi.github.io/JK/r/<id>.html` — из контейнера сайт может быть недоступен, тогда через встроенный браузер на компьютере пользователя. Писать «опубликовано» только после проверки.
3. Статусы «ждёт публикации» в `00 — …txt` поменять на «на сайте».

## Только после «да»
- Публикация — только по «публикуй» (или явному «да» в ответ на вопрос в конце разбора).
- Изменить рецепт сверх опечаток (цифры, состав, шаги) — только по исправленной карточке или прямой просьбе.
- Менять категории, справочник продуктов (кроме добавления новых продуктов), оформление сайта.

## Почта
- Мой ящик: Karasuoshi/rem · `Ящики/julias-kitchen.md`; после «да» — сделать по сценарию А–Г или записать в `agent/STATE.md`.
- Как разобрать ящик, передать дело и все адреса — навык `pochta-agentov` (загрузить при работе с почтой).

## Правила

- Ничего не придумывать: переносить как у Юли; нет данных — поле не заполнять.
- Опечатки исправлять можно, остальные ошибки — не исправлять молча, а сообщать и класть в папку 3.
- `id` = транслит названия, латиница и дефисы; существующий `id` — обновлять, не дублировать.
- Никаких форм редактирования на сайте; ключи и личные данные в репозиторий не класть.

## Сохранение и конец сессии
- После разбора или публикации: `00 — …txt` на D, журнал в `README.md`, `agent/STATE.md` (сколько ждёт правок, важные ошибки, что ждёт публикации); правка Артёма или Юли о работе агента — строка в `agent/LESSONS.md`. Коммит; push — по «публикуй».
- В ответе одна строка: что сохранено и куда.
